Bonus submissions
=================

1. Supporting different resolution requests
-------------------------------------------
Description:
  The simulator supports producing the output map at a resolution DIFFERENT from the input
  (hidden) map, and scoring it against that different-resolution ground truth.

  - A mission requests an output resolution via `output_mapping_resolution_factor`. The actual
    output-map voxel size is the mission's GPS precision (`gps_resolution_cm`) multiplied by that
    factor (the PDF describes the factor as "relative ... vs GPS"). A factor >= 1 is honoured and
    reported as ACCEPTED; a factor < 1 (finer than supported) is reported as IGNORED TOO SMALL and
    falls back to the x1 baseline, logged immediately.
    Implemented in `resolveOutputResolution`, src/SimulationRunFactoryImpl.cpp.
  - The output map is therefore written at its own resolution, which may differ from the input
    map's `map_resolution_cm`. The chosen resolution and its request status are reported per mission
    in `simulation_output.yaml` as `resolution_cm` and `resolution_request_status`.
  - `MapsComparison::compare` scores an output map against a ground-truth map of a DIFFERENT
    resolution: it evaluates on the origin (ground-truth) grid and samples every map by world
    position (`atVoxel`), so a target of a different resolution/offset is handled positionally.
    Implemented in src/MapsComparison.cpp.
  Note: cross-resolution comparison samples each ground-truth cell centre (correct for aligned /
  integer-ratio grids, which the tests and the provided dataset use); it is not a full
  area-weighted resample.

How to check:
  a) Run the dedicated test suite:
       ./build/drone_mapper_simulation_test --gtest_filter=BonusResolution.*
     It verifies: a coarse ground-truth vs a fine output of the same solid region scores 100 (both
     directions), a different-region pair scores 0, and end-to-end a factor=2 request is ACCEPTED,
     writes the output map at 20 cm (input map is 10 cm), and still scores in [0, 100].

  b) Observe it on the provided dataset:
       cd inputs && ../build/drone_mapper_simulation sim_compose.yaml ../out
     Then in ../out/simulation_output.yaml, the missions show `resolution_cm: 5` (the actual output
     resolution) differing from `map_resolution_cm: 10`, with `resolution_request_status: ACCEPTED`.

Test filter:
  BonusResolution.*
